You are a senior full-stack engineer. Build an MVP web app called “SignSalesIQ” for signage sales reps.

UPDATED GOAL
In addition to deterministic composited mockups (accurate perspective overlay), include an optional “Firefly Experimental Render” mode so we can evaluate how accurate Adobe Firefly is. The app must generate and store BOTH:
A) Deterministic Composite (baseline, perspective-correct)
B) Firefly Render (experimental AI render)
…and show them side-by-side with a simple accuracy scoring checklist.

TECH STACK (use this exactly)
- Frontend: Next.js 14 (App Router) + TypeScript + TailwindCSS
- Auth: NextAuth (Credentials provider) with bcrypt
- DB: PostgreSQL + Prisma
- Storage: local filesystem ./uploads (abstract for future S3)
- Image processing: Node server pipeline using sharp + node-canvas
- Background jobs: BullMQ + Redis (fallback to in-memory queue if Redis missing)
- External integration (optional): Adobe Firefly via a clean service wrapper (no hardcoded keys; use env vars)
- PDF export: pdf-lib (preferred) or React-PDF
- Validation: Zod

NON-NEGOTIABLE REQUIREMENTS
1) RBAC: ADMIN and SALES
2) Product Rules Engine: (locationType, signType, budgetRange) -> allowed products for GOOD/BETTER/BEST.
   - The system selects products; LLM may only explain them, not change them.
   - If sign type is Channel Letters: Good/Better/Best must respect the rules; budget-driven alternatives (e.g., pan sign) only allowed if rules explicitly permit.
3) “Grounded Mockup” Baseline:
   - Deterministic compositing is REQUIRED and is the primary output.
   - Do NOT rely on text-to-image generation for placement accuracy.
4) Firefly Experimental Render (NEW):
   - Add an optional pipeline that uses Adobe Firefly to produce an AI-rendered version of each tier.
   - This is for evaluation only and must be clearly labeled “Experimental / AI Render”.
   - Firefly cannot be the only output; always produce deterministic composite too.
5) Compliance Snapshot:
   - MVP: Template checklist + optional city/state via geocode stub.
6) Required Footer appears on exports and in UI per option:
   "Note on Scale: These visualizations are for conceptual sales purposes only. Sizes have been estimated based on standard architectural ratios. A physical site survey is required to confirm final dimensions and mounting requirements before fabrication."

F) Generation Pipeline (UPDATED to include Firefly)
When user clicks “Generate Good/Better/Best”:
- Always run deterministic composite jobs for all three tiers:
  - Create tier overlays from logo + optional business name text
  - Apply homography warp to plane
  - Blend onto photo (subtle shadow, opacity, edge soften)
  - Save outputs: outputs/{oppId}/{tier}/composite.png

- Optionally run Firefly experimental jobs if user toggles “Run Firefly AI Render”:
  - Inputs to Firefly should be controlled:
    1) Base Canvas photo
    2) A mask OR bounding region based on the selected plane (preferred)
    3) A reference overlay image (the deterministic composite result) as a guide (if supported by API; otherwise include it as an additional image input)
  - Goal: Firefly should “enhance realism” (lighting, shadow, reflections) and/or “integrate sign material look”
  - Save outputs: outputs/{oppId}/{tier}/firefly.png
  - Label clearly in UI as “Experimental (AI)”

IMPORTANT: If Firefly API is unavailable due to missing keys, the job should fail gracefully with a clear message and the deterministic composites still succeed.
